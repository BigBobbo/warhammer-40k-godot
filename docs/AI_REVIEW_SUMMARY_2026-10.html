How one review cycle works

Each proposal goes through the same five steps. A change goes into the game only if the evidence supports it.

01ObserveThe AI plays a full game in the real UI. Or a person presses K and reads the AI suggestion card.
02DiagnoseAn LLM reads the game log, the decision cards and the code. It finds the cause of each bad decision.
03ProposeThe LLM writes a change: a bug fix, a new rule, a weight value or a battle plan.
04MeasureAI-vs-AI games on the same dice seeds, both sides swapped. Result: VP per game, with error range.
05DecideA gate set before the run decides. Bug fixes ship without win-rate proof.
✔ ShipThe change is the new default.
○ Keep as optionThe code stays. The default is off or the change gives no gain.
✖ RejectThe change hurts or does nothing. A report records why.

Timeline

July review: the AI did not keep to its plan

An LLM watched a full Orks vs Custodes game. The AI made a new plan before each unit moved, so units did not keep to the plan. The game log also gave wrong reasons. The fix: one plan per Movement phase, kept until a unit needs a new order.

Grey bar: before. Blue bar: after. Each card uses its own scale. Shorter is better on all cards except the last one.

August test: an LLM as the army commander

An LLM read the board at the start of each battle round. It gave each unit an order: hold, push or hunt. The test ran 12 games on fixed dice seeds and compared each game with the same game without the LLM.

Row 1: LLM on Player 1 · Row 2: LLM on Player 2
  • 10 of 12 games were identical to the games without the LLM, VP for VP.
  • The 2 games that changed were worse: −12 and −5 VP.
  • Net effect: −1.4 VP per game. This is zero within the noise.
  • With 5× stronger orders, the AI obeyed about 95% of the orders. The result was still +0.3 VP.
  • Conclusion: the built-in AI already picks objectives about as well as the LLM. The team closed this line of work.

The difficulty levels now play differently

A review found seven difficulty switches in the code that no part of the AI used. The team connected them and measured each step. Most of the gain is between Normal and Hard. Result: the game now uses Competitive as the default (v1.41.0).

What the reviews taught

Structure beats small weightsChanges to how the AI plans (coordination, difficulty features, deployment) moved results. Changes to one weight value almost never did.
An LLM is a good reviewer, not a good playerLLM reviews found real bugs and wrong log text. An LLM that gives orders during play added nothing measurable. One call per action is too slow and costly.
Measure first, then shipIdeas that seemed correct, such as the scoring horizon, made the AI worse (−4.3 VP). The A/B gate stopped them.
Check the test boardOne test board had an extra 2000-point row. It let the AI put 69% of its army in reserve. Later tests used 2000-point boards built from real army lists.
Bug fixes need no win-rate proofA fix that makes the AI obey the rules ships even when the VP result is zero, for example the melee damage cap.
People find what tests missThe K card lets a player mark a suggestion "Good call" or "Bad call". Each mark saves a test case. Most October fixes started this way.
